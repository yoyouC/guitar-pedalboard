# 私有双桶社区写限流

发布、修订、点赞和举报各自使用独立策略，并且一次写操作必须同时取得成员桶和网络来源桶的容量。成员桶防止单一账号突发滥用，网络来源桶限制跨账号突发；任一桶不足时两个桶都不扣减。服务返回稳定的 `write_rate_limited`、操作类型、`Retry-After` 和绝对 `retryAt`，具体速率与突发阈值仅由部署配置决定，不进入公开 API 承诺。

生产适配器在事务内先确保两个桶存在，再锁定并原子更新，避免首次并发请求各自获得完整突发容量。成员 id 与代理提供的首个网络来源只在进程内计算 SHA-256，数据库只保存散列。网络来源用于滥用控制，不构成公开身份或行为分析资料。

新作品发布、声音修订追加和普通举报还要求登录身份具有已验证邮箱；拒绝响应提供站内验证入口。官方客户端保留编辑状态并展示验证或重试反馈。限流只位于写路径：公开读取、已加载内容和本地音频不访问限流存储，因此限流存储故障最多令相关社区写操作暂时不可用。
